# APP-COMMON-R1.6B — distributed revocation
Status: PARTIAL CODE ONLY / TESTS NOT EXECUTED / INDEPENDENT S2 HOLD

Implemented:
- Liquibase dispatcher migration with retry columns, consumer registry, monotonic ACK schema.
- Opt-in Keycloak admin service-account client; disable user + logout in shared realm; errors retain retryable outbox row.
- Scheduled DB-claimed worker, retries after two minutes, dispatch disabled by default.
- Scope-protected pull snapshot and consumer ACK endpoint; DB FK requires explicit registered consumer.
- Local monotonic snapshot enforcement primitive, unknown/stale state fail closed, duplicate/out-of-order protections and four unit tests.

P0 gaps / cannot claim accepted:
- The dispatcher currently marks an outbox event published after Keycloak action, **not after delivery to two resource servers**. It is NOT a distributed event bus.
- LocalRevocationSnapshot is a library primitive only, not wired into Collectra and App-B authentication filters. No end-to-end JWT rejection in either app has been proven.
- ACK request consumerId is self-declared; OAuth scope alone does not bind it to the calling service identity. Do NOT expose ACK endpoint in production until caller-to-consumer binding, version authenticity, replay protection and authenticated transport are implemented.
- No ACK aggregation transitions operation to ENFORCED; no consumer reconciliation, durable snapshot persistence, or 30-second propagation SLA.
- Keycloak admin role and secret provisioning, live Keycloak disable/logout tests, PostgreSQL integration/concurrency, fault injection, CI evidence and independent S2 review not completed.
- Global block endpoint remains non-idempotent; migration table exists but service does not use it.
- Fail-closed per-request PostgreSQL read is still active in App Common; target distributed cache replacement pending.

Required release proof:
1. Two **actual distinct** resource servers verify same Keycloak user JWT pre-block, then reject identical JWT post-block.
2. Durable per-consumer versioned event transport, authenticated ACK, verified ENFORCED transition.
3. Network partitions, stale snapshots, DB/Keycloak outage, duplicate and out-of-order event tests.
4. Operator-controlled client credentials and least-privilege Keycloak admin service account.
5. Independent S2 APPROVE with CI logs and observed propagation bound.

Do not enable dispatcher or ACK in production. `main` unchanged.
