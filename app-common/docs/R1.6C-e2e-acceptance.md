# APP-COMMON-R1.6C — Cross-App Enforcement E2E gate
Status: PARTIAL IMPLEMENTATION / NO LIVE E2E / S2 HOLD

## Added
- Migration r16c-001 binds registered revocation consumers to unique OAuth client IDs.
- Consumer snapshot and ACK endpoints derive consumer identity from validated JWT `azp`, not request body; future-version ACK rejected; monotonic ACK persistence.
- Reconciler transitions PROPAGATING to ENFORCED only if Keycloak applied and every enabled registered consumer has acknowledged version >= target.
- Reconciler disabled by default. Never enable before full mandatory-consumer registration and verified durable local application.

## Important remaining P0
1. **Collectra actual API is not yet wired to Keycloak resource-server revocation enforcement.** Its existing local JWT/auth path must be audited and migrated safely.
2. **App-B is not a deployed independent app.** Prior two-audience harness runs two instances of App Common, not Collectra and App-B.
3. Consumer ACK is authenticated to a registered OAuth client, but **not proof of actual local enforcement**; consumer must persist snapshot before ACK and attest to it in E2E. Operator must register all mandatory consumers or ENFORCED may be premature.
4. No durable push/pull consumer feed, periodic full reconciliation, or enforced 30s freshness bound. Snapshot lookup is per subject; no consumer-side integration yet.
5. Keycloak disable/logout is implemented in admin client but not verified against real Keycloak; outbox retries remain partial. No production-safe least-privilege provisioning yet.
6. Global block endpoint still lacks wired idempotency and event-loss/failure tests. Concurrent and partition recovery unproven.
7. No test execution, real two-application HTTP evidence, independent S2, or rollout plan.

## RED → GREEN acceptance suite required
- E2E-01: issue **one user access JWT** for Collectra API; pre-block 200; after block same JWT 401/403 at Collectra (not just App Common).
- E2E-02: issue user JWT for App-B; same subject; pre-block 200; after block same JWT 401/403 at App-B. OAuth audiences must remain isolated; a JWT issued for Collectra must never be accepted at App-B.
- E2E-03: disable Keycloak and logout; token refresh fails; existing access JWT is rejected by local revocation enforcement.
- E2E-04: drop, duplicate and reorder revocation events; no older ACTIVE state can undo a newer BLOCKED state; durable reconciliation repairs missed events.
- E2E-05: Keycloak unavailable; outbox retry persists and eventually succeeds, but protected APIs deny stale state.
- E2E-06: PostgreSQL unavailable; APIs fail closed after freshness expires; no false ENFORCED.
- E2E-07: ACK spoofing with another client and future version rejected; ENFORCED only after both verified consumers + Keycloak.
- E2E-08: concurrent block requests and idempotency-key replay preserve operation identity and monotonic versions.
- E2E-09: Collectra user UUID, org memberships, roles and legacy FK remain unchanged through identity link migration.
