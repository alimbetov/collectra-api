## 2. Blocking finding

### R-01 — PostgreSQL connection budget is exhausted by cached test contexts

Severity: BLOCKER before Slice 3

Evidence:

- the suite reaches `HikariPool-11`;
- the default Hikari maximum/minimum pool size is effectively too large for the
  number of cached unique Spring contexts;
- PostgreSQL rejects the next Liquibase connection with
  `FATAL: sorry, too many clients already`;
- all five reported errors belong to the same failed
  `MessageProcessingIntegrationTest` context; there are no assertion failures.

Resolution contract: [`integration-test-runtime.md`](integration-test-runtime.md).
The repair must constrain the test pool rather than raise production datasource
limits or Testcontainers PostgreSQL `max_connections`.

## 4. Open non-blocking findings

### R-05 — bundled CJK font is not actually accepted by the PDF renderer

Severity: BLOCKER before Slice 7, not before Slice 3

The existing locale test checks only the PDF signature and size, while the build
log reports:

```text
Couldn't load font (Noto Sans CJK SC)
Font metrics not available
```

Therefore a generated document can look technically successful while silently
missing Chinese glyphs. Slice 7 now has a glyph-level readiness gate. Fix the
font format/renderer compatibility or explicitly disable the affected locale
before attachment delivery.

### R-06 — existing identity Outbox events have no routes

Severity: P1 technical debt, outside communication Slice 3

Current application code appends:

- `TenantRegistered`;
- `UserInvitationCreated`;
- `PasswordResetRequested`.

The current `OutboxEventRouter` routes only `DOCUMENT_GENERATION_REQUESTED`, so
these identity events become `DEAD/UNKNOWN_EVENT_TYPE` when publishing is active.
Slice 3 should add only `MESSAGE_DELIVERY_REQUESTED`, not silently invent identity
queues. A separate product decision must either define consumers/routes or stop
creating those events. Resolve this before Slice 8 introduces Outbox DEAD alerts,
otherwise known dead identity events will create permanent false alarms.

### R-07 — `commons-logging.jar` remains on the classpath

Severity: P2 build hygiene

The warning is already covered by `docs/technical-audit-tz.md` section 12.4. Use
`mvn dependency:tree -Dincludes=commons-logging:commons-logging` and exclude only
the proven transitive source. It is not a reason to broaden the test-runtime
repair PR.
